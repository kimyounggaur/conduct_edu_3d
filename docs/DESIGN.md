## 0. 이 문서의 사용법

1. **1~3장**: 무엇을 만드는지 (목표 · 사용자 · 기능 범위). 방향이 맞는지 먼저 확인하세요.
2. **4장**: 앱에 들어갈 "지휘 지식"의 원본. 레슨 문구와 패턴 모양의 근거가 됩니다.
3. **5~8장**: 화면 · 데이터 · 엔진 · 기술 설계. AI에게 구현을 요청할 때 **장 번호를 그대로 인용**합니다. (예: "6.2의 Pattern 타입과 부록 A의 좌표를 그대로 코드로 옮겨 줘")
4. **9장**: 단계별 개발 계획. **한 번에 한 단계(Phase)만** AI에게 요청하고, 각 단계의 "완료 기준"으로 직접 검수합니다.
5. **10~12장**: 품질 · 위험 · 결정 사항. 12장의 결정 사항은 개발 시작 전에 확정하는 것을 권장합니다.

> 이 문서를 저장소의 `docs/DESIGN.md`로 두고, 프로젝트 `CLAUDE.md`에 "구현 전 docs/DESIGN.md의 해당 장을 먼저 읽을 것"이라고 적어 두면 AI가 매번 같은 기준으로 작업합니다.

## 1. 프로젝트 개요

### 1.1 한 줄 정의
초보자가 **지휘 박자 패턴을 쉬운 것부터 순서대로** 익히고 **예비박 · 시작 · 끝맺음 · 진입 신호(큐)** 까지 배울 수 있도록, **손과 지휘봉의 움직임을 궤적으로 보여 주고 메트로놈 박자에 맞춰 재생**하는 웹앱.

### 1.2 목표 (성공 기준)
- 설명 없이 **재생 버튼만 눌러도** "지금 몇 박인지, 손이 어디로 가는지"를 눈(궤적·번호)과 귀(클릭음)로 동시에 알 수 있다.
- 레슨을 순서대로 따라가면 혼자서 **기본 패턴 + 예비박 + 끝맺음 + 큐**를 익힐 수 있다.
- 속도(BPM)를 바꿔도 **궤적과 클릭음이 어긋나지 않는다.** (오차 ±10ms 이내, 5분 연속 재생 후에도 밀림 없음)
- 교실 TV/프로젝터(PC 브라우저), 태블릿 가로, 스마트폰 세로에서 모두 사용 가능하다.

### 1.3 대상 사용자
| 구분 | 대상 | 사용 상황 |
|---|---|---|
| 1차 | 학교 음악 교사, 학생(교과 '지휘하기' 단원), 합창단·동아리 초보 지휘자 | 수업 중 시연, 집에서 따라하기 |
| 2차 | 음악 전공 입시생, 대학 1학년(지휘 입문), 취미 학습자 | 자습, 템포 올리며 반복 연습 |

### 1.4 범위
| 구분 | 포함 내용 |
|---|---|
| **1차 출시(MVP)** | 레슨 커리큘럼(Lv1~Lv7), 패턴 궤적 2D 시각화 + 박자 재생, 예비박/시작/끝맺음, 진입 신호 기본, 설정·진도 저장(기기 내) |
| **2차** | 분할·불규칙 박, 셈여림/주법 변화, 늘임표(페르마타), 따라하기 평가(마우스/터치), **3D 뷰**(아바타 + 카메라 시점) |
| **추후 검토** | 웹캠 손 추적, 계정/클라우드 동기화, 실제 악보 연동 |

### 1.5 COND-211 공식 범위 ↔ 앱 레슨 매핑
| COND-211 범위 | 앱에서 다루는 레슨 (4.7 참조) |
|---|---|
| 지휘봉 기초 | Lv0 오리엔테이션(자세·지휘면·지휘봉 잡기·박점과 반동), Lv1 한 박 패턴 |
| 일반적인 박형 | Lv2~Lv4 (2·3·4박), Lv6 (6박), Lv11~Lv13 (5·7박, 불규칙, 분할) |
| 셈여림·아티큘레이션 표현 | Lv14 (크기 = 셈여림, 선의 성격 = 레가토/스타카토/마르카토) |
| 연주 시작 신호 | Lv5·Lv7 (예비박 I·II), Lv9·Lv10 (진입 신호 I·II) |
| 음악적 리더십 | Lv9·Lv10 (시선·예비·신호), Lv16 종합 (한 곡 전체 지휘) |

> 수집한 Berklee 자료는 **참고용**이며 이용조건상 재배포가 불가합니다. 앱의 모든 설명문·그림은 **자체 작성**하고, 참고 도서는 부록 C에 출처로만 표시합니다.

## 2. 핵심 용어 (앱 전체에서 통일)

| 용어(한국어) | 영문 | 뜻 | 앱에서의 표현 |
|---|---|---|---|
| 박자 패턴 | beat pattern | 한 마디 안에서 손이 그리는 정해진 도형 | "패턴" |
| 박점 | ictus | 박이 '찍히는' 순간과 지점 — 소리가 나는 타이밍 | 점 + 번호 + 번쩍임(플래시) |
| 반동 | rebound | 박점을 찍은 뒤 튀어 오르는 동작 | 궤적이 위로 솟는 부분 |
| 박점면 | beat plane | 모든 박점이 놓이는 가상의 수평선(면) | 연한 수평선 |
| 지휘면 | conducting frame | 손이 움직이는 범위 (어깨~허리, 몸 너비) | 캔버스 영역 |
| 예비박 | preparatory beat | 첫 소리 **한 박 전**의 동작 — 템포·호흡·셈여림을 미리 알림 | 주황 점선 궤적 + "숨↑" 아이콘 |
| 시작(센내기/여린내기) | attack (downbeat/upbeat start) | 첫 소리가 나는 박. 1박 시작 = 센내기, 못갖춘마디 시작 = 여린내기 | "시작!" 표시 |
| 끝맺음 | cutoff / release | 소리를 멈추게 하는 신호 | 작은 원 + 정지점 |
| 진입 신호(큐) | cue | 특정 파트에게 "지금 들어와"라고 알리는 신호 | 왼손 궤적 + 무대 배치도 강조 |
| 분할(세분박) | subdivision | 느린 템포에서 한 박을 둘/셋로 나눠 지휘 | 작은 보조 박점 |
| 불규칙 박 | asymmetric meter | 5/8, 7/8처럼 박 길이가 서로 다른 박자 | 긴 박은 더 긴·큰 궤적 |
| 잔상 | trail | 최근 0.5~1초 동안 지휘봉 끝이 지나간 자취 | 점점 옅어지는 선 |

### 3.2 사용자 시나리오
- **S1 교사(수업 시연)**: 홈 → "패턴 라이브러리" → 4박자 선택 → 60 BPM 재생 → TV에 띄우고 학생이 따라 함 → BPM 80으로 올림 → "한 박씩 보기"로 2박의 방향을 짚어 줌.
- **S2 초보 지휘자(여린내기 곡)**: Lv7 레슨 → "4/4, 4박에서 시작" 연습 선택 → 카운트인 1마디 → 예비박(3박 동작)이 주황으로 강조됨 → 시작 → 8마디 후 끝맺음(원형) → 템포 단계 60→80→100.
- **S3 학생(큐 연습)**: Lv10 레슨 → 합창 배치도 → 소프라노 2마디 1박, 알토 4마디 1박 진입 설정 → 재생 → 2박 전 "시선", 1박 전 "예비", 해당 박에 왼손 손바닥 신호가 궤적으로 표시됨.

## 4. 지휘 교육 내용 (도메인 지식 — 앱 설명문의 근거)

### 4.1 기본 원칙 5가지 (모든 레슨에서 반복)
1. **모든 박은 박점면 위에서 찍힌다.** 박점의 높이는 같다. (위로 가는 마지막 박도 박점은 아래 면에서 찍고 *찍은 뒤* 올라간다.)
2. **박점 직전에 빨라지고, 직후에 튄다.** 튀는 공처럼: 떨어질수록 가속 → 바닥(박점) → 반동으로 솟음 → 느려짐.
3. **1박은 항상 아래로, 마지막 박은 항상 위로.** 그래서 마디의 끝과 시작이 자연스럽게 이어진다.
4. **크기는 셈여림, 선의 성격은 주법.** 작게(p)·크게(f), 부드럽게(레가토)·끊어서(스타카토).
5. **모든 '시작'에는 한 박 전 예비 동작이 있다.** 첫 음, 파트 진입(큐), 끝맺음 모두 같은 원리.

| 2 | `TWO` | 2박 | 2/4, 2/2, 빠른 6/8(♩.=1박) | ① 아래 ② 바깥(오른쪽)으로 살짝 벌려 위 | 강-약 | |

### 4.3 박점·반동 모델 (궤적의 뼈대)
각 박 k는 세 가지 점으로 정의합니다.
- **P_k (박점)**: 박 k가 시작되는 순간 지휘봉 끝이 있는 위치. 항상 박점면 근처(y ≈ 0~0.1).
- **A_k (반동 정점)**: 박점을 찍은 뒤 튀어 오른 최고점. 박 길이의 약 35% 시점에 도달.
- **V_k (경유점, 선택)**: 다음 박점으로 가는 길의 중간 경유점 (예: 3박의 좌→우 가로지르기 곡선의 꼭대기).

한 박의 움직임 = `P_k → A_k → (V_k) → P_(k+1)`. 마지막 박은 `P_n → A_n → 꼭대기(0, 0.95) → P_1`로 돌아와 루프가 됩니다.

### 4.4 예비박 규칙
1. **시작하는 박의 "바로 앞 박" 동작을 한다.** 템포는 곡과 같게, 한 박 길이만큼.
2. 예비박 전에는 **정지(준비 자세)**: 지휘봉을 들고 1~2초 멈춰 시선을 모은다.
3. 예비박이 올라갈 때 **함께 숨을 들이쉰다.** (앱: "숨↑" 아이콘)
4. 예비박의 **크기와 성격**이 곡의 셈여림·주법을 미리 보여 준다.

**시작 박 → 예비박 동작 표**
| 박자 | 시작 박 | 예비박 동작 (= 앞 박의 동작) | 준비 자세 위치 |
|---|---|---|---|
| 2/4 | 1박 | 2박 동작(위로) | P₂ |
| 2/4 | 2박 | 1박 동작(아래로) | P₁ |
| 3/4 | 1박 | 3박 동작(위로) | P₃ |
| 3/4 | 2박 | 1박 동작 | P₁ |
| 3/4 | 3박 | 2박 동작(오른쪽) | P₂ |
| 4/4 | 1박 | 4박 동작(위로) | P₄ |
| 4/4 | 2박 | 1박 동작 | P₁ |
| 4/4 | 3박 | 2박 동작(왼쪽) | P₂ |
| 4/4 | 4박 | 3박 동작(오른쪽) | P₃ |
| 6/8 느린 | 1박 | 6박 동작 | P₆ |
| 6/8 느린 | 4박 | 3박 동작 | P₃ |

일반식: `예비박 = (시작박 − 1)`, 시작박이 1이면 `마디의 마지막 박`.
**반 박 시작('그리고'에서 시작, 예: 4/4의 4박 뒷 반 박)**: 기본은 **두 박 예비**(3박 동작 → 4박 동작 → '그리고'에서 시작)로 안정적으로 가르치고, 고급 옵션으로 **한 박 예비**(4박 동작만, 뒷 반 박에서 진입)를 제공.

### 4.5 끝맺음 규칙
- 끝맺음 = **예비(한 박 전 들어 올리기) + 끝맺음 동작(작은 원을 그리고 멈춤)**. 멈춘 자리에서 정지 = 소리가 끝남.
- 종류: `circle`(원형, 기본), `inward`(안쪽으로 수평 자르기), `outward`(바깥으로 자르기), `leftFist`(왼손을 쥐며 끝냄).
- 끝맺음 박 지정 예: 4/4에서 마지막 음이 4박까지 울리면 **다음 마디 1박에 끝맺음**; 2박 길이 음이 1박에 시작하면 **3박에 끝맺음**.
- 늘임표(페르마타, 2차): 유지 동작(손을 천천히 바깥으로) → 예비 → 끝맺음.

### 4.6 진입 신호(큐) 규칙
- **3단계**: ① 시선(1~2박 전, 해당 파트를 본다) → ② 예비(1박 전, 왼손을 들어 올린다) → ③ 신호(해당 박, 손바닥을 위로 '초대' / 가리키기 / 고개 끄덕임).
- 오른손 패턴은 **멈추지 않는다**(양손 독립).
- 왼손 기본 궤적: 대기 위치(명치 왼쪽) → 들어 올리기 → 파트 방향으로 손바닥 위로 → 1박 유지 → 1박에 걸쳐 복귀.
- 무대 배치도(데이터로 정의):
  - 오케스트라(지휘자 기준 왼쪽부터): 제1바이올린, 제2바이올린, 비올라, 첼로 / 뒤 왼쪽 콘트라베이스 / 중앙 목관 / 뒤 금관·타악
  - 합창: 소프라노 · 알토 · 테너 · 베이스 (2열 또는 4열 배치 선택)

## 6. 데이터 모델

### 6.1 좌표계
- **정규화 좌표**, 지휘자 본인 기준(오른손): `x ∈ [-1, 1]` (양수 = 지휘자의 오른쪽), `y ∈ [0, 1]` (0 = 박점면, 1 = 지휘면 꼭대기), `z ∈ [-0.3, 0.3]` (양수 = 앞쪽; 2D에서는 무시, **3D 뷰를 위해 처음부터 필드 확보**).
- 화면 변환(2D): `px = cx + sx · x · (view === 'audience' || leftHanded ? -1 : 1)`, `py = baseY − sy · y`. (`cx`=캔버스 가로 중앙, `baseY`=캔버스 높이의 80% 지점, `sx = 캔버스폭 × 0.40`, `sy = 캔버스높이 × 0.70`)
- 크기(셈여림) 배율 `s`: `x·s, y·s` (박점면 y=0은 고정).

### 6.2 패턴 정의 포맷
```ts
// src/engine/types.ts
export type Vec = [number, number] | [number, number, number]; // [x, y] 또는 [x, y, z]
export type Accent = 'strong' | 'medium' | 'weak';

export interface BeatDef {
  n: number;            // 박 번호 (1부터)
  P: Vec;               // 박점
  A: Vec;               // 반동 정점
  via?: Vec[];          // 경유점(0~2개)
  accent: Accent;
  r?: number;           // 반동 정점 도달 시점(박 길이 비율). 기본 0.35
  label?: Vec;          // 번호 표시 위치(기본: 박점 아래). 마지막 박은 꼭대기 근처
}

export interface PatternDef {
  id: string;                 // 'FOUR'
  nameKo: string;             // '4박자'
  level: number;              // 난이도(4.2 표)
  beats: BeatDef[];
  meters: string[];           // ['4/4', '4/2', '12/8']
  tempoUnit: '♩' | '♪' | '♩.' // BPM이 가리키는 음표
  base?: string;              // 파생 패턴이면 원본 id (예: 'THREE')
  weights?: number[];         // 박 길이 가중치. 기본 모두 1. 7/8(2+2+3) = [2,2,3]
  subdivide?: 2 | 3;          // 분할 패턴이면 분할 수 (규칙으로 보조 박점 생성)
  topPoint?: Vec;             // 마지막 박이 올라가는 꼭대기. 기본 [0, 0.95]
}
```

### 6.3 연습(Exercise) 정의 포맷 — "무엇을 재생할지"
```ts
export interface Exercise {
  id: string;
  patternId: string;
  tempo: { bpm: number; unit: '♩' | '♪' | '♩.' };
  bars: number;                 // 재생 마디 수 (0 = 무한, 루프)
  countIn: 0 | 1 | 2;           // 카운트인 마디 수
  readyHoldSec: number;         // 준비 자세 정지 시간(기본 1.5)
```

## 7. 핵심 엔진 설계 (순수 TypeScript, UI 의존 없음)

### 7.1 타임라인 엔진 — 박 시간 계산과 이벤트 생성 (`engine/timeline.ts`)
**입력**: `Exercise` + `PatternDef` → **출력**: `TimelineEvent[]` (시간순 정렬)

```
unitSec      = 60 / tempo.bpm                         // tempoUnit(가중치 1) 한 개의 길이
beatDur(k)   = unitSec × weights[k]                   // 7/8(2+2+3), ♪=180 → 0.667s, 0.667s, 1.0s
barDur       = Σ beatDur(k)

t = 0
push ready(t); t += readyHoldSec
if countIn > 0: for each 마디, 각 박 k: push countin(t, k); t += beatDur(k)
   (예비박은 카운트인의 '마지막 박' 동작으로 겹쳐서 push prep)
else: push prep(t, prepBeat, beatDur(prepBeat)); t += beatDur(prepBeat)
       (prep='twoBeat'면 두 박 push)
for bar = 1..bars: for k = startBeat..n (첫 마디만 startBeat부터): push ictus(t, bar, k, accent, dur); 
   subdivide/subdivisionClick이면 보조 ictus(sub=true) push; t += beatDur(k)
cue/cutoff/fermata: bar·beat → 시간으로 변환해 cueLook(t−lookBeatsBefore박), cuePrep(t−1박), cue(t) /
   cutoffPrep(t−1박), cutoff(t) push
push end(t)
```
- `prepBeat = start.beat === 1 ? n : start.beat − 1`
- half(반 박) 시작: 첫 ictus의 시작 표시 시각은 `t + beatDur/2`, 이벤트에 `half:true` 플래그.
- BPM 변경 시: 현재 박의 끝에서부터 새 템포로 **재계산**(현재 박 위치는 보존).

**검증(단위 테스트 필수)**
1. 4/4·♩=90·2마디·카운트인 0·start 1 → ictus 8개, 간격 0.6667s ±1e-9, 첫 ictus 시각 = 1.5 + 0.6667.
2. 7/8(2+2+3)·♪=180 → 박 길이 [0.667, 0.667, 1.0], 마디 길이 2.333s.
3. start 3(4/4) → prep.beat === 2; start 1 → prep.beat === 4.
4. cutoff(bar 3, beat 1) → cutoffPrep 시각 = cutoff 시각 − beatDur(4).

### 7.2 궤적 생성기 (`engine/trajectory.ts`)
**역할**: "지금이 박 k의 몇 %(phase)인가"를 받아 지휘봉 끝 위치를 돌려준다.

```
키프레임(한 마디, 박 k):  (0, P_k) → [(dwell, P_k)] → (r_k, A_k) → (f₁, V₁) … → (1, P_(k+1))
  · dwell: 주법에 따른 박점 정지 시간(비율). 보통 0
  · r_k  : 반동 정점 시점. 기본 0.35. 불규칙 박에서는 긴 박일수록 정점을 높게: A_y × (0.7 + 0.3·w_k/평균w)
  · via 시점 f_i: r_k와 1 사이를 균등 분할 (via 1개 → 0.68)
보간: 마디 전체 키프레임을 하나의 폐곡선으로 이어 centripetal Catmull-Rom 스플라인(루프 방지)
시간 이징(세그먼트별):
  · P→A: easeOutQuad (박점을 빠르게 떠남)   · A→V→P_next: easeInQuad (박점으로 가속)
  · 레가토: 전 구간 easeInOutSine, 직선성 없음
sample(beatIndex, phase) → {x, y, z}
samplePath(pattern, pointsPerBeat=100) → 고스트 도형용 폴리라인
```
**주법 파라미터 표**
| 주법 | r | dwell | 반동 높이 배율 | 경유점 가중치(1=곡선, 0=직선) |
|---|---|---|---|---|
| 레가토 | 0.45 | 0 | 0.8 | 1.0 |
| 보통(기본) | 0.35 | 0 | 1.0 | 0.8 |
| 스타카토 | 0.25 | 0.08 | 1.0 | 0.3 |
| 마르카토 | 0.30 | 0.05 | 1.25 | 0.5 |

**분할 패턴 생성 규칙**: 박 k의 보조 박점 `P'_k = P_k + 0.12 × dir_k` (dir_k = P_k→P_(k+1) 방향의 단위벡터, 마지막 박은 (0, +1)), 보조 반동 정점 높이 0.15, 시점 0.5.

**검증**: (a) `sample(k, 0)` = P_k 정확히 일치, (b) `sample(n−1, 1)` = P_1 (루프 연속), (c) 모든 phase에서 위치 변화량이 급변하지 않음(연속성), (d) 좌우 반전 시 x 부호만 바뀜.

### 7.3 오디오 스케줄러 (`engine/scheduler.ts`, `engine/clickSynth.ts`)
- **Web Audio API 직접 사용**(의존성 없음). 이유: 불규칙 박 길이를 자유롭게 다루고, 화면 동기화에 `audioContext.currentTime`(오디오 시계)을 그대로 쓸 수 있음. (Harmony에서 쓰는 Tone.js로 통일해도 되나, 이 경우 Transport의 박자표 기능 대신 **절대시간 스케줄링**을 사용할 것.)
- **미리 예약(lookahead) 방식**: 25ms마다 타이머가 돌며 "지금 + 100ms" 안에 있는 이벤트를 `OscillatorNode/BufferSource.start(절대시각)`으로 예약. 타이머는 **Web Worker**에서 돌려 백그라운드 탭 지연을 피함.
- 클릭음 합성: 강=1000Hz·60ms, 중강=850Hz·50ms, 약=700Hz·40ms, 보조박=600Hz·25ms·작게. 우드블록은 짧은 샘플(자체 제작/CC0).
- 예비박 클릭: 기본 **무음**(실제 지휘처럼) + 옵션으로 "틱" 소리. 카운트인은 일반 클릭.
- 음소거 모드: 스케줄러는 그대로 돌고 소리만 끔(시각 메트로놈 유지).
- 시작 절차: 재생 버튼 → `audioContext.resume()`(모바일 자동재생 정책) → `startTime = currentTime + 0.1` → 이벤트의 `t`에 `startTime`을 더해 예약.
- 지연 보정: 설정의 `audioOffsetMs`를 **화면 쪽**에 적용(블루투스 스피커 사용 시).

### 7.4 2D 렌더러 (`render/CanvasRenderer.ts`)
- **Canvas 2D**, `devicePixelRatio` 반영(흐림 방지), 60fps `requestAnimationFrame`.
- 매 프레임: `now = audioContext.currentTime − startTime + offset` → 타임라인에서 현재 구간(ready/prep/ictus k)과 phase 계산 → `trajectory.sample` → 그리기. **setInterval이 아니라 오디오 시계 기준**이므로 누적 밀림이 없음.
- 레이어(아래→위):
  1. 박점면(점선), 전체 고스트 도형 + 번호 (패턴/옵션이 바뀔 때만 오프스크린 캔버스에 다시 그림)
  2. 예비박 구간이면 해당 박의 궤적을 주황 점선으로, 끝맺음/큐 구간이면 해당 궤적 강조
  3. 잔상: 최근 `trailMs` 동안의 위치를 링 버퍼로 저장, 투명도 1→0·굵기 4→1px로 폴리라인
  4. 지휘봉/손: 궤적점 = 지휘봉 끝. 손 위치 = 끝 + (0.22, −0.16), 팔꿈치 고정점 (0.45, −0.45)에서 손까지 아래팔 선(선택). 맨손 모드는 손 아이콘의 검지 끝 = 궤적점
  5. 박점 플래시: ictus 시각 통과 시 해당 P_k에 반지름 0.5→1.2배 링이 150ms 동안 퍼짐, 현재 박 숫자가 120%→100%로 '통' 튐
  6. 왼손 레이어(7.5), 오버레이 텍스트("준비", "숨↑", "시작!", "정지")
- 정지 상태에서는 준비 자세 위치(예비박 박점)에 지휘봉을 그려 둠.

### 7.5 왼손 레이어 (`engine/gestures/*.ts`)
왼손은 오른손 패턴과 **별도 트랙**(시간 → 위치 + 손 모양)으로 정의합니다.
```ts
interface GestureTrack { id: string; keyframes: Array<{ tBeats: number; pos: Vec; pose: 'rest'|'open'|'palmUp'|'point'|'fist' }> }
```
- 대기 위치 `[-0.35, 0.12]` (명치 왼쪽), 큐 들어 올림 `[-0.30, 0.55]`, 큐 신호: 무대 배치도의 대상 방향으로 뻗음 (왼쪽 파트 `[-0.75, 0.55]`, 중앙 `[-0.15, 0.70]`, 오른쪽 파트는 `[0.00, 0.65]`까지만 — 몸을 가로지르지 않음).
- 큐 트랙: `cuePrep(−1박)`에서 들어 올리기 → `cue(0)`에서 뻗음+palmUp → `+1박` 유지 → `+2박`까지 복귀.
- 끝맺음(왼손): `cutoffPrep(−1박)` 들어 올림 `[-0.30, 0.50]` → `cutoff(0)` 반지름 0.10 원을 0.5박에 그리고 `[-0.22, 0.42]`에서 fist로 정지.
- 끝맺음(오른손/지휘봉): 마지막 박점에서 `[0.10, 0.60]`까지 들어 올림 → 반지름 0.12 원 → `[0.18, 0.40]`에서 정지, 이후 오른손 패턴 중단.
- 무대 배치도 패널: 작은 캔버스/SVG. 지휘자(하단 중앙), 파트 블록. `cueLook` 구간엔 눈 아이콘+대상 깜빡임, `cue`에 화살표.

### 7.6 3D 뷰 (2차, `render3d/`)
- **같은 궤적 샘플러**를 사용. z는 기본 0, 패턴 데이터에 z를 넣으면 깊이 표현 가능(예: 1박에서 살짝 앞으로).
- 구현: Three.js + `@react-three/fiber`. 단순 아바타(몸통·머리·위팔·아래팔·손·지휘봉)를 **2관절 IK**(어깨 고정, 손 목표 = 궤적점)로 움직임. 왼손도 동일.
- 카메라 프리셋: 지휘자 뒤(거울과 같은 좌우), 청중 정면, 측면(깊이·지휘봉 각도 확인). 드래그로 자유 회전.
- 무대 배치도를 3D 바닥에 블록으로 배치해 큐 방향을 입체로 표시.
- 성능 목표: 태블릿에서 60fps. 저사양이면 2D로 자동 전환.

### 7.7 따라하기 평가 (2차, `engine/evaluate.ts`)
- 입력: 캔버스 위 포인터(마우스/터치) 좌표를 ≥60Hz로 기록 `(x, y, t)`.
- 박점 감지: 속도의 국소 최소값이면서, 전후 50ms 이동 벡터의 각도 변화가 90° 이상인 지점.
- 매칭: 감지된 박점을 예정된 ictus 시각과 ±150ms 창에서 짝지음(가장 가까운 것).
- 점수: 박마다 타이밍 오차(|Δt| ≤ 50ms 초록, ≤120ms 노랑, 그 외 빨강) + 위치 오차(정규화 거리 ≤ 0.15 양호). 마디 점수 = 평균. 놓친 박·추가 박 감점.
- 피드백: 박점에 색 링, 마디 끝에 "타이밍 92% · 위치 80%", 레슨 통과 기준(예 80%).

## 9. 단계별 개발 계획

> 진행 방식: ① 해당 Phase를 AI에게 요청(아래 예시 문구 사용, 문서 장 번호 인용) → ② "완료 기준"을 직접 확인 → ③ 문제는 구체적으로 적어 수정 요청 → ④ 통과하면 다음 Phase. **한 Phase에 한 번의 큰 요청, 수정은 작은 요청 여러 번.**

### Phase 0 — 프로젝트 준비 (규모 S)
- **목표**: 빈 앱이 로컬과 Vercel에서 뜬다.
- **작업**: Next.js 15 + TS 생성, Tailwind + shadcn/ui, ESLint/Prettier, Vitest, 8.2 폴더 뼈대, `docs/DESIGN.md` 복사, `CLAUDE.md`에 "구현 전 설계문서 해당 장 읽기" 규칙, GitHub 저장소 + Vercel 연결.
- **완료 기준**: `npm run dev` → 브라우저에 "지휘 기초" 제목 표시 / `npm test` 실행됨(테스트 0개 통과) / Vercel 미리보기 URL 접속.
- **AI 요청 예시**: "docs/DESIGN.md 8장의 스택과 폴더 구조대로 Next.js 15 프로젝트를 만들어 줘. 홈에 '지휘 기초' 제목만 보이면 돼. Vitest가 돌아가게 하고 CLAUDE.md에 설계문서 참조 규칙을 넣어 줘."
- **내가 확인할 것**: 브라우저 제목, Vercel 주소.

### Phase 1 — 엔진 1: 패턴 데이터 · 타임라인 · 궤적 (규모 M)
- **목표**: 화면 없이도 "언제, 어디에" 지휘봉 끝이 있어야 하는지 계산된다.
- **작업**: 6.2 타입, 부록 A 좌표 입력(ONE~SEVEN + 파생 규칙), 7.1 타임라인, 7.2 궤적 생성기(주법 파라미터 포함), 7.1/7.2의 검증 항목을 단위 테스트로.
- **완료 기준**: `npm test` 전부 통과(테스트 이름이 한글로 읽히게: "4/4 90bpm 2마디 박 시각", "루프 연속성" 등) / `npm run demo:trajectory` 같은 스크립트로 4박자 궤적 200점을 PNG 또는 SVG로 저장해 **도형이 교과서 4박자와 같은지 눈으로 확인**.
- **AI 요청 예시**: "docs/DESIGN.md 6.2·6.3·6.4의 타입과 부록 A 좌표를 engine/patterns에 입력하고, 7.1 타임라인과 7.2 궤적 생성기를 구현해 줘. 7.1과 7.2의 '검증' 항목을 Vitest 테스트로 만들고, 4박자 궤적을 SVG로 저장하는 스크립트도 만들어 줘."
- **내가 확인할 것**: 테스트 초록 표시, SVG 도형이 ①아래 ②왼쪽 ③오른쪽 ④위 모양인지.

### Phase 2 — 시각화 + 재생 (규모 L) ← **MVP의 핵심**
- **목표**: 패턴 라이브러리 화면에서 모든 패턴을 골라 소리와 함께 재생된다.
- **작업**: 7.3 스케줄러·클릭음, 7.4 2D 렌더러(고스트·잔상·지휘봉·플래시·번호), 5.3 트랜스포트(재생/일시정지/정지/루프/한 박씩/카운트인/BPM/TAP), 5.4 옵션 중 시점·왼손잡이·지휘봉·잔상·고스트·번호·박점면·클릭음, 단축키, `/library` 화면.
- **완료 기준(검수 체크리스트)**:
  - [ ] 재생 시 클릭음과 박점 플래시가 **동시에** 느껴진다 (PC 스피커, 이어폰 각각).
  - [ ] BPM 40·60·120·200에서 모두 도형이 같고 속도만 다르다.
  - [ ] 5분 재생 후에도 클릭과 그림이 어긋나지 않는다.
  - [ ] 일시정지 → 재개 시 같은 박에서 이어진다. 정지 시 준비 자세로 돌아간다.
  - [ ] 지휘자/청중 시점, 왼손잡이 전환 시 좌우가 반전된다.
  - [ ] 한 박씩 ▷ 를 누르면 1초에 걸쳐 다음 박점으로 이동하고 멈춘다.
  - [ ] 탭을 다른 탭으로 바꿨다 돌아와도 박자가 밀리지 않는다.
  - [ ] 아이폰/아이패드 사파리에서 첫 터치 후 소리가 난다 (무음 스위치 안내 문구 표시).
  - [ ] 고해상도 화면에서 선이 흐리지 않다.
- **AI 요청 예시**: "7.3 오디오 스케줄러와 7.4 2D 렌더러를 구현하고, 5.2 와이어프레임의 /library 화면에 5.3 트랜스포트와 5.4 옵션(시점·왼손잡이·지휘봉·잔상·고스트·번호·박점면·클릭음)을 붙여 줘. 화면 동기화는 반드시 audioContext.currentTime 기준으로."
- **내가 확인할 것**: 위 체크리스트를 PC·아이패드·안드로이드 폰에서 각각.

### Phase 3 — 레슨 시스템 (규모 M)
- **목표**: 홈의 커리큘럼 맵에서 Lv0~Lv4 레슨을 순서대로 학습하고 진도가 저장된다.
- **작업**: 6.5 레슨 포맷·6.6 저장, `/` 커리큘럼 맵, `/lesson/[id]` 화면(좌 레슨 패널 단계 진행, 시연 자동 재생, 따라하기 템포 단계 버튼, 체크리스트, 퀴즈), Lv0~Lv4 레슨 원고 입력(부록 B 형식), `/progress`, `/help`.
- **완료 기준**: 레슨을 끝까지 진행하면 홈 카드에 완료 표시 / 새로고침해도 진도 유지 / 레슨 패널의 "시연" 클릭 시 해당 Exercise가 자동 재생 / 퀴즈 오답 시 해설 표시 / 폰 세로에서도 모든 단계 조작 가능.
- **AI 요청 예시**: "6.5·6.6 포맷으로 레슨 시스템을 만들고 4.7 표의 Lv0~Lv4 레슨 JSON을 부록 B 형식으로 작성해 줘. 홈 커리큘럼 맵과 레슨 화면(5.2)을 구현하고 진도는 localStorage에 저장해."
- **내가 확인할 것**: 레슨 문구가 4.1 원칙과 맞는지(특히 "마지막 박의 박점도 아래 면" 설명), 어린 학생이 읽어도 이해되는지.

### Phase 4 — 예비박 · 시작 · 끝맺음 (규모 M)
- **목표**: 시작 박을 바꾸면 예비박이 자동으로 바뀌고, 지정한 박에서 끝맺음한다.
- **작업**: 6.3 Exercise의 `start/prep/cutoff/countIn`, 7.1의 ready/countin/prep/cutoffPrep/cutoff/end 이벤트, 7.4 오버레이(주황 점선 예비박, "숨↑", "시작!", "정지"), 7.5 끝맺음 궤적(오른손 원형 / 왼손 주먹), 라이브러리에 시작 박·끝맺음 설정 UI, 레슨 Lv5·Lv6·Lv7 원고.
- **완료 기준**: 4.4 표의 11가지 조합을 돌렸을 때 예비박 동작이 표와 일치(테스트로도 고정) / 카운트인 1마디일 때 마지막 박에서 예비박이 겹쳐 움직임 / 끝맺음 후 지휘봉이 정지점에 멈추고 클릭이 끊김 / 반 박 시작에서 "두 박 예비"와 "한 박 예비" 옵션이 모두 동작.
- **AI 요청 예시**: "4.4·4.5 규칙과 6.3·7.1의 prep/cutoff 사양대로 예비박·시작·끝맺음을 구현해 줘. 4.4 표 전체를 테이블 테스트로 고정하고, 7.4·7.5의 오버레이와 끝맺음 궤적을 그려 줘. Lv5·6·7 레슨 원고도 작성."
- **내가 확인할 것**: 4/4·4박 시작 곡(여린내기)에서 예비박이 '오른쪽으로 가는 3박 동작'인지.

### Phase 5 — 진입 신호(큐) (규모 M)
- **목표**: 파트와 박을 지정하면 시선→예비→신호가 왼손 궤적과 배치도에 표시된다.
- **작업**: 4.6 규칙, 6.3 `cues`, 7.5 큐 트랙, 무대 배치도 패널(오케스트라/합창 2열/4열), 큐 설정 UI, 레슨 Lv9·Lv10(돌림노래 SAT 순차 진입 예시).
- **완료 기준**: 큐 2박 전 배치도에서 대상 파트가 깜빡이고 눈 아이콘 표시 / 1박 전 왼손이 올라감 / 해당 박에 손바닥 신호 + 화살표 / 오른손 패턴은 그대로 진행 / 큐 3개가 겹치지 않고 순서대로.
- **AI 요청 예시**: "4.6과 7.5의 큐 트랙·무대 배치도를 구현하고 Exercise.cues를 지원해 줘. Lv9·Lv10 레슨 원고 작성."
- **내가 확인할 것**: 왼손이 몸을 가로질러 오른쪽 끝까지 가지 않는지, 시선 표시 타이밍.

### Phase 6 — 고급 패턴과 표현 (규모 M, 2차)
- **작업**: 5·7박·분할·불규칙 패턴 라이브러리 노출(데이터는 Phase 1에 이미 있음), 주법·크기 옵션 연결, 늘임표, 음성 카운트(선택), 레슨 Lv8(6박은 1차에 포함)·Lv11~Lv15.
- **완료 기준**: 7/8(2+2+3)에서 세 번째 박의 클릭 간격이 길고 궤적도 그만큼 길게·높게 / 스타카토에서 박점에 잠깐 멈춤이 보임 / 크기 0.6과 1.25에서 박점면이 고정된 채 도형만 커짐.

### Phase 7 — 따라하기 평가 (규모 L, 2차)
- **작업**: 7.7, 레슨 '따라하기' 단계에 점수 연결, 결과 화면.
- **완료 기준**: 정확히 따라 그리면 90% 이상, 박자를 틀리면 빨강 표시 / 터치 기기에서 손가락으로 가능.

### Phase 8 — 3D 뷰 (규모 L, 2차)
- **작업**: 7.6. 카메라 프리셋 3종, 아바타 IK, 큐 방향 3D 표시, 저사양 2D 자동 전환.
- **완료 기준**: 2D와 3D의 박점 타이밍이 같음(같은 샘플러) / 측면 시점에서 지휘봉 각도·깊이 확인 가능 / 아이패드 60fps.

### Phase 9 — 마무리와 배포 (규모 M)
- **작업**: 반응형 점검(TV 1080p·태블릿·폰), 접근성(키보드·명도 대비·축소 모션 설정 존중), PWA/오프라인, 성능 측정(FPS·오디오 지터 로그), 도움말, 피드백 링크, 도메인.
- **완료 기준**: 10장의 기기 매트릭스 전부 통과 / Lighthouse 성능·접근성 90 이상.

## 10. 품질 · 테스트 계획

### 10.1 자동 테스트(Vitest)
- 타임라인: 정박/불규칙/카운트인/시작 박/끝맺음/큐 시각 (표 기반 테스트)
- 궤적: 박점 일치, 루프 연속성, 반전, 주법 파라미터별 dwell
- 스케줄러: 가짜 오디오 시계로 예약 누락·중복 없음, BPM 변경 후 재계산
- 평가(2차): 합성 입력으로 박점 감지 정확도

### 10.2 수동 검수(기기 매트릭스)
| 기기/브라우저 | 확인 항목 |
|---|---|
| PC Chrome / Edge (1080p TV 포함) | 동기화, 단축키, 전체 화면 |
| iPad Safari (가로) | 첫 터치 오디오, 무음 스위치 안내, 60fps |
| iPhone Safari (세로) | 레이아웃, 터치 조작 |
| Android Chrome (폰·태블릿) | 오디오 지연 보정 효과 |

### 10.3 성능 예산
- 프레임 55fps 이상 유지, 오디오 예약 지터 5ms 미만(개발자 모드 로그), 첫 화면 로드 2초 이내(4G).

## 11. 위험 요소와 대응

| 위험 | 영향 | 대응 |
|---|---|---|
| 패턴 모양이 교재·학파마다 다름 (6박, 7박, 4박의 '4' 위치) | "틀렸다"는 피드백 | 패턴을 **데이터로 분리**해 교체·추가 가능. 기본값은 한국 교과서 그림과 맞춤. 레슨에 "교재에 따라 다를 수 있음" 명시 |
| 모바일 자동재생 정책·iOS 무음 스위치 | 소리 안 남 | 재생 버튼에서 `resume()`, 무음 스위치 안내, 시각 메트로놈 항상 제공 |
| 백그라운드 탭 타이머 지연 | 박자 밀림 | Worker 타이머 + 오디오 시계 기준 렌더링 |
| 블루투스 스피커 지연 | 그림과 소리 어긋남 | 지연 보정 설정(ms) + 보정 가이드 화면 |
| Canvas 흐림(고해상도) | 품질 저하 | devicePixelRatio 스케일링 |
| 범위 확대(3D·웹캠·계정) | 출시 지연 | 1차 MVP 범위 고정(1.4), 3D는 같은 데이터로 2차 |
| 참고 자료 이용조건(Berklee) | 저작권 | 자체 문구·그림만 사용, 출처는 링크 표기 |
| 비개발자 검수 한계 | 버그 누락 | 각 Phase의 체크리스트를 **눈·귀로 확인 가능한 문장**으로 작성(9장) |

## 12. 결정이 필요한 사항 (추천안 포함)

| # | 결정 사항 | 선택지 | 추천 | 이유·영향 |

| 1 | 2D 먼저 vs 3D 먼저 | 2D→3D / 3D 단독 | **2D 먼저, 3D는 Phase 8** | 패턴 학습의 핵심은 평면 도형·타이밍. 2D는 의존성 없이 2~3단계면 쓸 수 있음. 3D 먼저 가면 아바타·IK·카메라 때문에 출시가 크게 늦어짐. 데이터에 z를 넣어 두어 3D 전환 비용 최소화 |
| 2 | 프레임워크 | Next.js 15 / Vite+React | **Next.js 15** | 기존 표준 스택·Claude Code 설정 재사용. 서버 기능은 안 씀 |
