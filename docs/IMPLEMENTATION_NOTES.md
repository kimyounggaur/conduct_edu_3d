# 구현 메모 — 설계문서와 달라진 점

설계문서(`docs/DESIGN.md`)를 기준으로 구현하면서, 그대로 옮기면 문제가 생기거나 문서에 정해지지 않았던 부분을 어떻게 정했는지 적어 둔다.
새로 바꾸는 사람은 이 표에 한 줄씩 추가한다.

## Phase 1 (엔진)

| 항목 | 설계문서 | 구현 | 이유 |
|---|---|---|---|
| 박 번호 위치 | 마지막 박 번호는 꼭대기 근처 (부록 A `label`) | 모든 번호를 박점면 아래 한 줄에 두고, 겹치면 자동으로 간격을 벌림 | 4.1 원칙 1("마지막 박도 박점은 아래 면에서 찍는다")과 그림이 어긋나 혼란. 번호 줄이 왼쪽→오른쪽으로 "2 1 4 3"처럼 읽힘 |
| 한 박 패턴 모양 | 박점 → 정점 → 박점 (같은 선) | 내려오는 길에 경유점 `(-0.06, 0.5)` 추가 → 좁은 고리 | 올라가는 선과 내려오는 선이 완전히 겹쳐 방향을 알 수 없었음 |
| 마지막(위로 가는) 박의 정점 | `A`에서 r=0.35 | 꼭대기(마지막 경유점)를 정점으로, r = 주법값 + 0.15 (보통 0.5) | `A`에서 멈췄다가 다시 올라가는 어색한 움직임 방지. 꼭대기에서 가장 느려지고 1박으로 떨어짐 |
| 정점에서의 속도 | 정점에서 완전히 0 | 주법별 최저 속도 비율(레가토 0.35, 보통 0.12, 스타카토 0, 마르카토 0.05) | 완전히 멈추면 정점마다 "턱" 걸리는 느낌 |
| 레가토 가감속 | 전 구간 easeInOutSine | 올라갈 때 easeOutSine, 내려갈 때 easeInSine + 최저 속도 0.35 | 박 전체에 easeInOutSine을 쓰면 박점에서 손이 멈춰 보이고 정점에서 가장 빨라져 지휘 동작과 반대 |
| 박점 모양 | (명시 없음) | 박점마다 선을 나눠 그려 박점에서 방향이 꺾임 | 스플라인 하나로 이으면 박점이 둥글게 뭉개지고 박점면 아래로 파고듦 |
| 화면 변환 | `sx = 폭×0.40`, `sy = 높이×0.70` (가로·세로 따로) | 가로·세로 같은 배율 `min(높이×0.70, 폭/1.6)` | 화면 비율마다 도형이 찌그러짐 (4:3에서 가로가 76%로 눌림) |
| 좌우 반전 식 | `view==='audience' \|\| leftHanded` | `(view==='audience') !== leftHanded` | 청중 시점 + 왼손잡이를 함께 켜면 원래 방향이 맞음 (두 번 뒤집기) |
| 못갖춘마디 마디 번호 | 첫 마디를 1마디로 | 1박이 아닌 박에서 시작하면 그 마디는 0마디, 다음이 1마디 | 악보 관례(못갖춘마디는 마디 번호에 넣지 않음) |
| 끝맺음 없이 끝나는 연습 | (명시 없음) | 마지막 박 다음 1박 자리에 손이 내려와 멈춤 (소리 없음, `end` 이벤트) | 7.1 검증 1("2마디 → 박점 8개")과 일치 |
| 예비박 종류 | `auto / twoBeat / none` | `oneBeat` 추가 | 4.4의 "반 박 시작 + 한 박 예비"(고급 옵션)를 표현하려면 필요 |
| 패턴 정보 | 6.2 필드 | `timeSignature`, `summary`, `release`, `defaultBpm` 추가 | 라이브러리 화면 표시용 |
| 불규칙 박 반동 | `0.7 + 0.3·w/평균w` | 설계 그대로 | 모양 차이는 작고 주로 시간(길이)으로 드러남 → Phase 6에서 다시 확인 |

## Phase 2 (재생·화면)

| 항목 | 설계문서 | 구현 | 이유 |
|---|---|---|---|
| 트랜스포트 위치 | 화면 맨 아래 전체 폭 (5.2) | 캔버스 바로 아래 (가운데 칸) | 모든 화면 크기에서 조작 버튼이 그림 가까이 있고, 휴대폰 순서(캔버스 → 트랜스포트 → 탭)와도 같음 |
| 3칸 배치 시작 폭 | (명시 없음) | 1280px 이상에서 3칸, 768~1279px은 2칸(오른쪽에 패턴/보기 설정 탭) | iPad 가로(1024px)에서 3칸이면 캔버스가 너무 작아짐 |
| 소리-그림 동기 | `audioContext.currentTime` 기준 | `getOutputTimestamp()`로 "지금 스피커에서 나오는 소리의 시각" 기준 + 수동 보정값(`audioOffsetMs`) | currentTime은 출력 지연만큼 소리보다 앞서 있어 그림이 먼저 움직임 |
| 재생 중 반복·카운트인 변경 | (명시 없음) | 다음 재생부터 적용 | 재생 중 바꾸면 박 위치를 다시 계산해야 해 혼란 |
| 잔상 그리기 | 투명도 1→0 | 8겹 띠를 겹쳐 그려 오래된 쪽은 가늘고 옅게 | 선분마다 따로 그리면 이음매가 구슬처럼 진해짐 |
| 아래팔 | 선택 | 손에서 팔꿈치 쪽으로 옅어지는 선 | 진한 띠는 그림을 가로질러 산만함 |
| 큰 박 숫자 색 | 박 세기 색 | 강박·중강박은 파랑, 약박은 회색 잉크 | 약박 색(#93C5FD)은 큰 글자로 쓰면 흰 바탕에서 잘 안 보임 |
| 무음 스위치(iOS) | 안내 문구 | 안내 문구 + `navigator.audioSession.type = "playback"`(지원하는 Safari) | 지원 기기에서는 무음 모드에서도 클릭이 들림 |
| 숫자 글꼴 | (명시 없음) | 박자표·음표는 Bravura에서 필요한 글자만 뽑아 이름을 바꾼 OFL 파생 글꼴(10KB) | 악보와 같은 숫자 모양. OFL 규정상 수정본은 원래 이름(Bravura)을 쓸 수 없어 "Podium Numerals"로 바꿈 |
| 홈 화면 | 커리큘럼 맵 (Phase 3) | 지금은 소리 없는 4박자 시연 + 배우는 순서 목록, 패턴이 있는 단계는 패턴 연습으로 연결 (`/library?pattern=FOUR`) | Phase 3 전에도 앱 구조를 확인할 수 있게 |
| 점검용 주소 | — | `/library?debug` 이면 `window.__conductor`로 엔진 접근 | 브라우저에서 소리-그림 동기를 재는 점검 스크립트용 |

## 화면 단순화 (Phase 2 마무리 후)

연습 화면에 조작이 한꺼번에 약 48개 떠 있어 산만했다. "지금 하려는 일 — 박자 고르기, 재생, 빠르기"만 앞에 두고 나머지는 서랍으로 보냈다. 엔진·저장 형식·단축키는 그대로이고 화면 조각만 바뀌었다.

| 항목 | 이전 (설계 5.2~5.4, Phase 2 구현) | 지금 | 이유 |
|---|---|---|---|
| 연습 화면 배치 | 3칸(패턴 목록 · 그림 · 보기 설정) + 아래 단축키 줄 | 한 줄기: 박자 버튼 → 그림 → 설명 한 줄 → 조작줄. 가운데 정렬, 폭은 화면 높이에 맞춰 그림(4:3)이 한눈에 들어오게 | 눈이 갈 곳이 세 군데로 나뉘어 그림에 집중이 안 됨 |
| 박자 고르기 | 22개 목록이 항상 왼쪽에 (설명 포함) | 한 박·2박자·3박자·4박자 버튼 + "다른 박자" 서랍(나머지 18개). 서랍에서 고르면 버튼이 파랗게 채워지고 이름은 그림 왼쪽 위에 표시 | 배우는 순서의 앞쪽 4개를 가장 많이 씀. 키보드 1~4와 같은 순서 |
| 보기 옵션 | 오른쪽에 항상 열림 | 위쪽 "설정" 서랍 | 한 번 정하면 거의 안 바꿈 |
| 카운트인·반복·빠르기 탭 | 조작줄에 항상 | "설정" 서랍의 '연습' 묶음. 기본값(카운트인 1마디, 반복 켜짐)은 그대로 | 기본값으로 충분하고 자주 안 바꿈 |
| 한 박씩(이전·다음) | 조작줄 | 조작줄에 남김. 순서는 정지 · 이전 · 재생 · 다음 | 방향을 가르치는 핵심 도구라 서랍으로 보내면 교실에서 쓰기 불편 |
| 그림 안 글자 | 박자표 + 이름 + 설명 + 현재 박 + 마디 + 빠르기 | 박자표 + 이름 + 현재 박. 설명은 그림 아래 한 줄. 빠르기는 조작줄에 이미 있어 뺌 | 같은 정보가 두세 군데 겹쳐 있었음 |
| 마디 번호 | 박 숫자 아래 "37마디"가 계속 바뀜 | 숨김. 준비·카운트인·예비박·끝 같은 상태 글자만 보임 (`BeatDisplay`의 `showBar`로 다시 켤 수 있음) | 계속 바뀌는 글자가 시선을 끎 |
| 단축키 안내 | 화면 아래 줄 | 설정 서랍 맨 아래. 서랍이 열려 있거나 다른 곳에서 이미 처리한 키(서랍을 닫는 Esc)에는 반응하지 않음 | 서랍을 Esc로 닫을 때 재생이 같이 멈추는 것을 막음 |
| 서랍을 닫은 뒤 초점 | (서랍 없음) | 마우스·터치로 닫으면 초점을 놓고(바로 Space로 재생), 키보드로 닫으면 열었던 버튼으로 돌려줌 (`src/lib/drawerFocus.ts`) | 초점이 "설정" 버튼에 남으면 Space가 재생 대신 서랍을 다시 열어 버림. 키보드 사용자는 자리를 잃으면 안 됨 |
| 상단 메뉴 | "배우는 순서 / 패턴 연습" 두 탭 | 로고(홈으로)와 "설정" 버튼 | 화면이 둘뿐이라 메뉴가 필요 없음 |
| 홈 | 소개 + 배우는 순서 17단계 목록 (10개는 "레슨 준비 중") | 소개 한 줄 + "연습 시작" + 시연. 목록은 레슨이 생기는 Phase 3에서 `src/content/curriculum.ts`로 다시 만든다 | 누를 수 없는 줄이 절반이었음 |

## 패턴 모양 확인
`npm run demo:trajectory` → `docs/pattern-previews/all-patterns.svg`(전체), `four-articulations.svg`(주법 비교).
회색 점은 같은 시간 간격으로 찍은 위치라, 점이 촘촘한 곳은 느리게(반동 정점), 듬성한 곳은 빠르게(박점 직전) 움직인다.
